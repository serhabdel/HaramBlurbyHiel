# Security Policy

## Reporting Security Vulnerabilities

**Please do not open public issues for security vulnerabilities.**

Instead, email: **security@haramblur.app**

We take security seriously and will respond within 48 hours.

### What to Include

- Description of the vulnerability
- Steps to reproduce
- Potential impact
- Suggested fix (if any)
- Your contact information

### Response Process

1. **Acknowledgment** - Within 48 hours
2. **Investigation** - Within 1 week
3. **Fix Development** - Timeline communicated
4. **Release** - Coordinated disclosure
5. **Recognition** - Credit given (with your permission)

## Security Measures

### Data Privacy

- ✅ All content analysis happens on-device
- ✅ No screenshots stored permanently
- ✅ No user data sent to servers
- ✅ No analytics or tracking
- ✅ Encrypted local storage

### Permissions

The app requires these permissions:

| Permission | Purpose | Required |
|------------|---------|----------|
| Accessibility Service | Detect screen content | Yes |
| Overlay | Display blur | Yes |
| Internet | Prayer times API | No (optional) |
| Location | Prayer times calculation | No (optional) |

### Code Security

- ProGuard/R8 obfuscation enabled
- No hardcoded credentials
- Secure signing process
- Regular dependency updates

## Security Best Practices for Users

1. **Download only from official sources**
2. **Keep the app updated**
3. **Review permissions granted**
4. **Report suspicious behavior**

## Known Limitations

- Detection accuracy varies by content type
- False positives may occur
- Battery usage increases with active monitoring
